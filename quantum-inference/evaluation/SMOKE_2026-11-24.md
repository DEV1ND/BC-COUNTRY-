## Test harness correction

An earlier smoke workflow version expected `response_mode=model_generation` and `is_model_generation=true`. The deployed legacy Candidate API did not expose those fields even though it identified the generated response as `quantum-bpe-candidate` and `is_live_inference=true`. The harness was corrected to identify the legacy model-generation route using those existing fields and to report quality separately from execution success.

The next technical investigation should prioritize tokenizer training corpus coverage, BPE merge behavior, training-target alignment, and a fresh held-out evaluation after any separately approved candidate training run.
